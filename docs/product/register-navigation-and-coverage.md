# Register navigation and coverage

Growing registers keep their existing workspace and selected-record interfaces.
Previous/Next controls sit in the register footer, outside the scrolling rows.
The shared footer offers **Rows per page: 25 / 50 / 100**, with 25 as the default.
Each register remembers its own choice in that browser. This stores only a UI
preference; workflow records remain in their authoritative sources. A size change
starts at the first page and retains search/filter inputs and open review drafts.
Register table scrolling returns to the top of the new page. Row numbers continue across pages. Changing a search or filter starts at the
first page; a source change can require **Refresh first page**.

Search applies to the owner collection, rather than only the visible rows.
Some searches inspect a bounded window of owner pages. If that window contains
no match but older pages remain, **Continue search** remains available. That is
not an empty-collection result. A missing collection total stays unknown.
Source denial, malformed continuation and stale originals are errors, not empty
successful lists. Loading retains the workspace frame; obsolete reads are
cancelled when selection changes.

## Workspace behavior

- Proposal follows its native continuation and keeps independently inspectable
  originals. Repository requests verify the original receipt before confirmation;
  a summary omitting receipt details does not reopen a resolved request.
- Repository search follows native custody pages and reconciles Inventory and
  private registration evidence. Summary cards retain the independent overview;
  searching or paging the register does not change their scope.
- Registry retains the canonical Inventory/private-record reconciliation. The
  initial combined bundle is paged locally; subsequent private pages do not
  repeat the legacy Inventory rows.
- Prototype pages contain selected projects and their referenced owner evidence.
  An independently selected original does not enter page counts. Native source
  confirmations retain their original meaning and evidence. Summary cards use
  the separate complete overview, with unknown values shown as an em dash.
- Orchestration pages reach older Temporal executions. Its definition register
  pages the complete admitted catalog locally without changing which definitions
  the owner admits. Original run inspection is independent of the
  visible run page.
- Managed Products reads a WGCF product page with its current original readiness
  evidence. Product inspection can read an exact original outside the page.
- Delivery Work Design and Refinement search canonical source status. Saved-work
  progress remains visible separately and does not become a global source filter.
  Current scope excludes completed, retired and parked packages; History retains
  them. The global Execution Board and dependency model remain separate reads.
  Evidence cells show a short preview; full evidence text remains available in
  the hover title and existing selected-package inspection.
  Each status and Family Map column has an independent compact search. Searching
  retains its total badge and normal card height; crowded columns scroll.
  Execution cards and the selected-package heading show the known ART type and
  number, such as **Epic 39**. Full source references remain available in hover
  titles and inspection; column search matches either identity.
- Delivery Home and Catalog always show the current projection. Their compact
  scope switcher stays right-aligned above the section navigation, shows Current
  and is disabled. Returning to the work sections restores the last selected work scope.
- Delivery Intake History reads bounded native admission evidence directly.
  Evidence issues remain visible in a compact notice with inspectable details.
  Unknown global totals use **—** in the existing summary cards; they are not
  inferred from the current page. Package History
  retains its exact original read and locked workflow controls.
- Lifecycle's **Workspace overview** keeps source readbacks and the bounded
  workflow journal together, with partial coverage disclosed. **Workflow journal**
  uses the same register and detail interface to search and continue older
  recorded workflow decisions. Source readbacks do not acquire journal approvals.
- Dev Integration and Governed Releases reuse their native filtered pages and
  totals. Source revisions bind continuation; a changed source requires starting
  again. Request/result and original workflow histories retain their own paths.

Model Purpose profiles, Registered Models and Workflow Routing use the shared
footer over their complete configuration snapshots. Search/filter changes reset
to page one, including clearing a search. Their existing columns, selected
profile, System default route and guarded routing drafts remain intact.
Repository Requests searches the native Proposal collection through a bounded
read adapter; it does not treat the overview's loaded subset as complete.

Nested operational histories use the same range and Previous/Next presentation:
Model profile requests and runtime operations, Registry promotion/lifecycle
requests, repository and direct Registry onboarding, repository setup requests,
Dev Integration profile requests, and Platform operations in both Environment
workspaces. Native cursors/offsets remain source owned. Original request evidence,
unsaved review inputs and global pending-request protection remain independent
of the visible page. Setup history uses an opt-in owner register view; an older
owner's recent-only response explicitly discloses unavailable older history.
A failed page read is unavailable, not an empty result. Explicit refresh/retry
uses the consumer's stated current-page or restart-first-page behavior.

Provider/profile choice dropdowns and individual-operation event trails remain
record-scoped controls rather than global paginated registers.
Global boards, dependencies and attention must retain global coverage or clearly
state incomplete coverage; a visible page never establishes global completeness.
Private project records do not gain automatic AI access from register navigation.

## Source and operating proof

These changes are staged in a preview maintenance batch. The OOS register reader
and WGCF product query must be deployed with their matching Console consumer
before native paging is operationally qualified. A compatibility read is allowed
only from a verified complete older response or a provably complete short list.
It never invents continuation for a full legacy page. Preview fixtures prove
presentation and interaction; they do not prove live owner mutations or runtime
acceptance. Backend dependencies land before the dependent Console consumer.

Shared paging text uses the same compact metadata component as Proposal,
including loading and empty states. Footers retain spacing without an extra
divider. Intake keeps exact source/evidence references in technical disclosure;
readable source and receipt labels lead in the register.


## Display windows and native reads

A display size is separate from a source transport limit. Readers compose or
slice only enough already-validated native 20/25/100-record pages for the selected
window, with bounded reads and the existing deadlines. Window cursors contain
native continuation, scope, size, intra-page position and an identity fingerprint;
they never contain project records or credentials. Source cursors pass unchanged
to their original APIs. Changing scope/size starts a new window. Drift, denial,
malformed continuation and contradictory source counts fail visibly; none become
partial successful pages. Sparse bounded searches retain **Continue search**.

Absolute-offset readers keep stable revision/total checks. Complete configuration
snapshots resize locally. Original model/Platform request inspection and pending
request protections remain independent of page counts. Buttons and the selector
respect pending commands and guarded request states.

Workspace Registry is the native exception: its page digest is reused in later
operations, so the existing owner reader accepts 25/50/100 directly and signs the
actual page. The Console verifies that exact page and requested bound. This owner
extension must be published before larger private Registry pages can be qualified;
the Console does not forge a larger signed page from several smaller ones.
The mixed Registry also retains the boundary between legacy Inventory and a signed
private page. A shorter display window can still have continuation at that source
boundary; the size is an upper bound and is never evidence of collection completeness.

Primary Console activity retains its distinct purpose and controls. Choice
fields and individual-record event trails do not acquire register pagination.
