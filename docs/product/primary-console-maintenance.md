# Primary Console operation and maintenance

Operator-approved owner maintenance preserves the Command Center, monitor,
agent, account and Activity interfaces. The existing Console design profile,
source responsibility rules and native Teras modal foundation remain binding.

## Operator interpretation

- Source loading is distinct from owner failure. Incomplete initial reads cannot
  claim an outage, a zero workspace total, or current executable routes.
- Monitor observations identify their source and coverage. No-alert text must
  reflect connected components. Agent path reachability does not prove model
  entitlement, approval or a successful generation.
- Workspace Pulse summarizes projected work, not whole-system availability.
  Retained failed operations keep their owner state, timestamp and exact next
  action. A newer successful operation cannot silently supersede another intent.
- Priority details/actions follow the filtered queue. No match has no actionable
  selected priority.

## Governance Activity

The existing inline panel and Activity History share display projections over
unchanged canonical events. Show a readable action, the known subject type/name,
result and source. Do not invent project names, accepted decisions or causal
meaning from a hash. Exact identifiers and original summaries remain inspectable
as technical evidence and in JSON export.

Routine evidence reads are available through an explicit all-events choice;
operator activity is the default. The interface shows how many loaded events
are hidden by that choice. Source/outcome/search operate over loaded events and
say so. A partial window is not a complete audit history.

History extends the same OOS/WGCF cursor reads in bounded pages on explicit
request. The browser supplies only closed owner selectors and bounded opaque
cursors, never credentials, endpoints or arbitrary paths. Failed continuation
retains existing events and offers retry; identical events deduplicate and
conflicting owner identities fail closed. Initial source refreshes do not erase
an operator's loaded history. Export describes exactly its loaded coverage.
The Console remains a projection, not a second ledger or owner authority.

## Layout and interaction

Reserve the fixed dock lanes at every supported desktop width. Existing panels
reflow below a 1200px usable stage: the existing side columns and selected
detail must fit together without covering monitor tabs or list rows. Verify
selection, switching and deselection as well as the unselected panel. Runtime
detail facts and source references wrap without truncating original values. Long identifiers
must wrap inside their content containers in both inline and history views.
Expanded agents reuse the existing native modal foundation while preserving
session/controller state and the existing compact appearance. Workspace-hosted
floating agents retain their existing portal behavior.

Monitor tabs expose tab/tabpanel relationships and arrow/Home/End navigation.
Native expanded-modal focus, Escape, return focus and background containment
must work for keyboard and pointer users.

## Qualification

Dock space is reserved once by the Console frame; the command header and
Workbench launcher reflow within the remaining stage. Registers retain all
columns through their existing bounded scroll pattern. Evidence cards retain
their content height, and environment readiness, capabilities and history use
one explicit scrolling content region. A selected Proposal shows a short
overview with its next action; its complete original context remains in the
Proposal Hub, details and owner-backed workflow inputs. Capture wording follows
the same live/disconnected mode as the existing capture dialog.

Source review and acceptance are distinct from live qualification. Validate
projection, loading/failure, filtering and cursor boundaries, then inspect the
real accepted-source UI with short and long event types at 1200, 1440, 1700 and
1920 pixels. Check containment, mouse clicks, keyboard navigation, modal focus,
partial-history access and exact original evidence. Preserve source, save and
workflow authority boundaries. Installer and remote/team identity remain outside
this repair.

## Power-user language

Preserve precise domain vocabulary, identifiers, original owner explanations
and technical evidence. Primary copy connects the operation, affected subject,
result and available next action. Expand OOS/CGG on first explanation and state
what a reachability probe does and does not establish. Do not infer a project
name or causal explanation from a digest. Technical evidence is inspectable,
not replaced by vague reassurance. Routine successful reads can be filtered;
failed reads or events with required next actions remain operator-visible.

VMEM cards and chart legends use the compact `VMEM` label and numeric
committed/limit values. The selected detail view retains the accounting explanation.
